# 广告平台后端 API 接口对接文档

## 一、文档说明

本文档面向前端开发人员，描述「基于 Web 的互联网广告平台系统」后端 API 的对接方式。文档内容依据后端实际代码逐项核实，覆盖 13 个接口的请求规格、响应格式、鉴权方式与错误码，可作为前端开发的直接对接依据。

后端技术栈为 Django 5.2 + Django REST Framework 3.18 + MySQL 8.0。所有接口统一返回 JSON，字符编码为 UTF-8，时间字段采用 ISO 8601 格式（如 `2026-11-24T10:03:36.007958+08:00`），金额字段为字符串形式的十进制数（如 `"200.00"`），前端展示时需自行转换为 Number 并注意精度。

### 1.1 服务地址

实验阶段后端服务监听本机 `http://127.0.0.1:8000`。所有接口路径均以此为基础地址拼接。部署环境变化时，仅需替换基础地址部分。

### 1.2 接口总览

系统共 13 个接口，分为三类：面向前端用户的接口（使用 Token 鉴权）、面向管理员的接口（Token + 管理员权限）、面向合作网站的对外接口（使用 Api-Key 鉴权）。

| 序号 | 接口 | 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|------|------|
| 1 | 注册 | POST | /api/register | 无 | 客户/管理员注册 |
| 2 | 登录 | POST | /api/login | 无 | 签发 Token |
| 3 | 广告列表 | GET | /api/client/ads | Token | 前端查看本人广告 |
| 4 | 新建广告 | POST | /api/ads | Token | 创建广告并送审 |
| 5 | 待审核列表 | GET | /api/audit/pending | Token + 管理员 | 管理员查看待审核广告 |
| 6 | 审核通过 | POST | /api/audit/{id}/pass | Token + 管理员 | 通过后进入投放池 |
| 7 | 审核驳回 | POST | /api/audit/{id}/reject | Token + 管理员 | 需填写驳回原因 |
| 8 | 充值 | POST | /api/recharge | Token | 更新余额并记流水 |
| 9 | 充值流水 | GET | /api/recharges | Token | 查看本人充值记录 |
| 10 | 站内信 | GET | /api/notifications | Token | 查看通知列表 |
| 11 | 数据报表 | GET | /api/report | Token | 汇总统计 |
| 12 | 对外拉广告 | GET | /api/ads | Api-Key | 合作网站拉取可投放广告 |
| 13 | 事件回传 | POST | /api/track | Api-Key | 曝光/点击上报 |

## 二、鉴权约定

### 2.1 用户 Token 鉴权

除注册、登录与两个对外接口外，所有接口均需在请求头携带 Token：

```
Authorization: Token <登录返回的 token 值>
```

Token 在登录接口成功响应中返回，同一账号重复登录复用同一 Token。前端应将 Token 持久化保存（如 localStorage），并在每次请求时附带。缺少或无效的 Token 返回 401，响应体为 `{"detail": "身份认证信息未提供。"}` 或 `{"detail": "认证令牌无效。"}`。

注意：后端仅接受 Token 鉴权，不依赖浏览器会话（Cookie/Session）。前端无需处理 CSRF Token。

### 2.2 管理员权限

审核相关接口（序号 5、6、7）在 Token 鉴权基础上，额外要求账号具备管理员标记。普通客户访问返回 403，响应体为 `{"detail": "您没有执行该操作的权限。"}`。前端应据此在界面层区分普通客户与管理员的功能入口。

### 2.3 对外接口 Api-Key 鉴权

两个对外接口（序号 12、13）使用 Api-Key 鉴权，请求头写法为：

```
Api-Key: test-api-key-2026
```

**重要**：必须使用连字符形式 `Api-Key`，不可写成下划线形式 `api_key`。Django 开发服务器会剥离请求头名中带下划线的项，导致下划线写法鉴权失败并返回 401。当前实验阶段的 Api-Key 值为 `test-api-key-2026`，正式部署时由服务端环境变量配置。

### 2.4 两类广告接口的区分

路径 `/api/ads` 同时承载两个语义不同的接口，前端务必区分：

- `GET /api/ads` 是对外接口，供合作网站使用 Api-Key 拉取全部可投放广告。
- `POST /api/ads` 是用户接口，供当前登录客户使用 Token 新建广告。
- 前端查看本人广告列表应使用独立路径 `GET /api/client/ads`，不要误用 `GET /api/ads`。

## 三、用户接口详解

### 3.1 注册

- 方法与路径：POST /api/register
- 鉴权：无

请求参数：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| phone | string | 是 | 手机号，唯一，不可重复 |
| password | string | 是 | 密码，长度不少于 6 位，服务端以 PBKDF2 哈希存储 |
| nickname | string | 否 | 昵称，默认空字符串 |

请求示例：

```json
{"phone": "13800000001", "password": "test123456", "nickname": "客户"}
```

成功响应（201 Created）：

```json
{
  "message": "注册成功",
  "user": {
    "client_id": 1,
    "phone": "13800000001",
    "nickname": "客户",
    "balance": "0.00",
    "is_admin": false,
    "reg_time": "2026-11-24T10:03:36.007958+08:00"
  }
}
```

失败响应：手机号重复返回 400，响应体为 `{"phone": ["具有 phone 的 client 已存在。"]}`；密码过短返回 400 并在响应中说明字段错误。

### 3.2 登录

- 方法与路径：POST /api/login
- 鉴权：无

请求参数：`phone`（手机号）、`password`（密码），均必填。

成功响应（200 OK）：

```json
{
  "token": "4a07eae5fcbe...",
  "user": {
    "client_id": 1,
    "phone": "13800000001",
    "nickname": "客户",
    "balance": "200.00",
    "is_admin": false,
    "reg_time": "2026-11-24T10:03:36.007958+08:00"
  }
}
```

失败响应：手机号或密码错误返回 400，响应体包含「手机号或密码错误」。账号被停用返回 400 并提示「账号已停用」。

用户对象字段说明：`client_id` 为用户编号，`balance` 为账户余额（字符串形式的金额），`reg_time` 为注册时间，`is_admin` 为布尔值，标识该账号是否为管理员，前端可据此决定是否显示审核管理入口（普通客户为 false，管理员为 true）。响应中的 `user` 对象字段与客户端展示所需一致，可直接用于渲染用户信息。

### 3.3 查看广告列表

- 方法与路径：GET /api/client/ads
- 鉴权：Token

无需请求参数，返回当前登录客户自己的全部广告，按提交时间倒序排列。

成功响应（200 OK）为数组，每个元素结构如下：

```json
[
  {
    "ad_id": 25,
    "client_id": 46,
    "title": "测试广告",
    "content": "文案",
    "image_url": "http://x/i.png",
    "landing_url": "http://x",
    "daily_budget": "100.00",
    "spent": "0.01",
    "status": "pending",
    "submit_time": "2026-11-24T11:03:05.351791+08:00",
    "reject_reason": null
  }
]
```

广告字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| ad_id | number | 广告编号 |
| client_id | number | 所属客户编号 |
| title | string | 广告标题 |
| content | string | 广告文案 |
| image_url | string | 图片地址 |
| landing_url | string | 落地页地址 |
| daily_budget | string | 日预算（金额字符串） |
| spent | string | 已消耗金额（金额字符串） |
| status | string | 状态：pending 待审核 / approved 通过 / rejected 驳回 / paused 暂停 |
| submit_time | string | 提交时间（ISO 8601） |
| reject_reason | string 或 null | 驳回原因，未驳回时为 null |

### 3.4 新建广告

- 方法与路径：POST /api/ads
- 鉴权：Token

请求参数：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| title | string | 是 | 广告标题 |
| content | string | 否 | 广告文案 |
| image_url | string | 否 | 图片地址 |
| landing_url | string | 否 | 落地页地址 |
| daily_budget | string/number | 是 | 日预算，金额格式 |

请求示例：

```json
{
  "title": "测试广告",
  "content": "文案",
  "image_url": "http://x/i.png",
  "landing_url": "http://x",
  "daily_budget": "100.00"
}
```

成功响应（201 Created）返回新建广告的完整对象，结构与 3.3 中的元素一致，其中 `status` 固定为 `pending`，`spent` 为 `"0.00"`。

注意：`ad_id`、`spent`、`status`、`submit_time`、`reject_reason` 为服务端只读字段，前端提交时无需传入，传入也会被忽略。新建的广告不会立即进入投放池，须经管理员审核通过。

### 3.5 充值

- 方法与路径：POST /api/recharge
- 鉴权：Token

请求参数：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| amount | string/number | 是 | 充值金额，必须大于 0 |
| order_no | string | 是 | 订单号，全局唯一 |

请求示例：

```json
{"amount": "200.00", "order_no": "ORD20261124001"}
```

成功响应（200 OK）：

```json
{"message": "充值成功", "balance": "200.00"}
```

失败响应：金额格式错误返回 400「充值金额格式错误」；金额非正数返回 400「充值金额必须大于 0」；订单号为空返回 400「订单号不能为空」；订单号重复返回 400「订单号已存在」。

业务规则：充值成功后立即更新账户余额并记录流水；若充值后余额低于 50 元，系统自动生成一条余额提醒站内信。接口响应中的 `balance` 为更新后的最新余额，前端可据此直接刷新余额显示，无需再查用户信息。

### 3.6 查看充值流水

- 方法与路径：GET /api/recharges
- 鉴权：Token

无需请求参数，返回当前客户的充值记录，按充值时间倒序排列。

成功响应（200 OK）：

```json
[
  {
    "recharge_id": 22,
    "amount": "200.00",
    "order_no": "CURL1795489382",
    "recharge_time": "2026-11-24T11:03:06.550332+08:00"
  }
]
```

### 3.7 查看站内信

- 方法与路径：GET /api/notifications
- 鉴权：Token

无需请求参数，返回当前客户的站内信，按创建时间倒序排列。

成功响应（200 OK）：

```json
[
  {
    "notice_id": 30,
    "title": "广告审核结果",
    "content": "您的广告《测试广告》已审核通过，进入投放池。",
    "is_read": false,
    "create_time": "2026-11-24T11:03:06.106290+08:00"
  }
]
```

字段说明：`is_read` 为是否已读标记（布尔值）。站内信由审核动作（通过/驳回）与低额余额预警自动生成，标题分别为「广告审核结果」与「余额提醒」。当前接口仅提供列表查询，未提供标记已读接口，前端的红点提醒逻辑需自行按 `is_read` 字段在本地实现。

### 3.8 数据报表

- 方法与路径：GET /api/report
- 鉴权：Token

无需请求参数，返回当前客户名下广告的汇总统计，供前端图表使用。

成功响应（200 OK）：

```json
{
  "ad_count": 1,
  "impression_count": 1,
  "click_count": 1,
  "total_spent": "0.01"
}
```

字段说明：`ad_count` 为广告数量，`impression_count` 为曝光次数，`click_count` 为点击次数，`total_spent` 为总消耗金额（金额字符串）。该接口返回汇总值，不提供按时间筛选的参数，前端图表可按此口径展示总体数据。

## 四、管理员接口详解

### 4.1 查看待审核列表

- 方法与路径：GET /api/audit/pending
- 鉴权：Token + 管理员权限

无需请求参数，返回全部状态为待审核的广告，按提交时间正序排列。响应结构与 3.3 的广告列表一致。非管理员访问返回 403。

### 4.2 审核通过

- 方法与路径：POST /api/audit/{id}/pass
- 鉴权：Token + 管理员权限

路径参数 `{id}` 为广告编号。无需请求体。

成功响应（200 OK）返回更新后的广告对象，其中 `status` 为 `approved`。同时系统自动向广告所属客户发送一条标题为「广告审核结果」的站内信。

失败响应：广告不存在或不在待审核状态返回 404，响应体为 `{"detail": "广告不存在或不在待审核状态"}`。已通过的广告不可重复通过。

### 4.3 审核驳回

- 方法与路径：POST /api/audit/{id}/reject
- 鉴权：Token + 管理员权限

路径参数 `{id}` 为广告编号。请求体必须包含驳回原因：

```json
{"reason": "素材违规"}
```

成功响应（200 OK）返回更新后的广告对象，其中 `status` 为 `rejected`，`reject_reason` 为填写的原因。同时自动向客户发送站内信，内容包含驳回原因。

失败响应：未填写原因返回 400「驳回必须填写原因」；广告不存在或不在待审核状态返回 404「广告不存在或不在待审核状态」。已驳回的广告不可再执行通过操作。

## 五、对外接口详解

### 5.1 拉取可投放广告

- 方法与路径：GET /api/ads
- 鉴权：Api-Key

请求头携带 `Api-Key`。无需请求参数。返回全部审核通过且日预算未耗尽的广告，按提交时间倒序排列，响应结构与 3.3 的广告列表一致。

无符合条件的广告时返回空数组 `[]`（200 OK），这是正常业务响应，不是错误。Api-Key 缺失或错误返回 401 且不返回任何业务数据。

### 5.2 事件回传

- 方法与路径：POST /api/track
- 鉴权：Api-Key

请求参数：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| ad_id | number | 是 | 广告编号 |
| event_type | string | 是 | 事件类型：impression 曝光 / click 点击 |
| source | string | 否 | 来源标识，默认空字符串 |

请求示例：

```json
{"ad_id": 25, "event_type": "click", "source": "partner-a"}
```

成功响应（201 Created）：`{"detail": "ok"}`。

失败响应：Api-Key 错误返回 401「Unauthorized」；`event_type` 非 impression 或 click 返回 400「event_type 无效」；广告不存在返回 400「广告不存在」。

业务规则：每次回传写入一条展示记录；点击事件额外累加广告消耗，单次点击消耗 0.01 元。该消耗会反映在广告的 `spent` 字段与报表接口的 `total_spent` 中。

## 六、错误码汇总

| HTTP 状态码 | 含义 | 常见场景 |
|-------------|------|----------|
| 200 | 成功 | 查询类接口、登录、充值、审核动作 |
| 201 | 创建成功 | 注册、新建广告、事件回传 |
| 400 | 请求参数错误 | 密码错误、手机号重复、金额非法、驳回无原因、event_type 无效 |
| 401 | 未认证或鉴权失败 | Token 缺失/无效、Api-Key 缺失/错误 |
| 403 | 权限不足 | 非管理员访问审核接口 |
| 404 | 资源不存在或状态不符 | 审核目标广告不存在或不在待审核状态 |

所有错误响应均为 JSON 格式，错误信息在 `detail` 字段（或序列化器的字段错误对象中）返回，前端可直接提取展示。

## 七、前端接入建议

1. **认证流程**：应用启动时读取本地保存的 Token；若无 Token，跳转登录页。登录成功后保存 Token 并进入主界面。所有受保护请求在请求拦截器中统一注入 `Authorization: Token <token>`。
2. **响应拦截**：对 401 响应清除本地 Token 并跳转登录页；对 403 响应提示无权限；对 400 响应展示 `detail` 或字段错误信息。
3. **金额处理**：所有金额字段为字符串，展示前转换为 Number；涉及计算的场景注意使用适当的精度处理，避免浮点误差。
4. **状态映射**：广告状态为英文枚举值，前端展示时映射为中文标签：pending 待审核、approved 已通过、rejected 已驳回、paused 已暂停。
5. **接口区分**：前端广告列表使用 `GET /api/client/ads`，对外拉广告 `GET /api/ads` 仅供合作网站使用，两者不可混用。
6. **图片与落地页**：`image_url` 与 `landing_url` 由前端提交完整地址，后端仅做存储与返回，不做校验。
7. **报表图表**：数据报表接口返回汇总值，可直接作为 ECharts 等图表组件的数据源。

## 八、联调验证说明

后端已提供可重复执行的端到端测试脚本，位于 `backend/tests/curl_test_final.sh`。该脚本覆盖全部 13 个接口与鉴权边界，执行后各接口均返回预期状态码，并核对点击消耗为 `0.01` 元。前端开发人员可运行此脚本确认后端服务处于可用状态：

```bash
bash "D:/软件工程作业/backend/tests/curl_test_final.sh"
```

脚本会自动清理历史测试账号，可重复执行。若脚本全部通过，说明后端服务与数据库正常，可开始前端联调。
